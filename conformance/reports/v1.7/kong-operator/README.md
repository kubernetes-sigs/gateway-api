## Reproduce

These reports were generated by the [Kong Operator conformance workflow run for v2.4.0](https://github.com/Kong/kong-operator/actions/runs/44297012626).

### Prerequisites

- [kind](https://kind.sigs.k8s.io/), [Helm](https://helm.sh/), [mise](https://mise.jdx.dev/), and the Go version specified in `go.mod`.
- Set `KONG_LICENSE_DATA` to a valid Kong Gateway Enterprise license, as in the CI workflow.
- For hybrid mode only, set `KONG_TEST_KONNECT_ACCESS_TOKEN` to a Konnect access token and `KONG_TEST_KONNECT_SERVER_URL` to `us.api.konghq.tech`, the endpoint used by the CI workflow.

### Steps

1. Clone the Kong Operator repository and check out the tested release:

   ```bash
   git clone https://github.com/Kong/kong-operator.git
   cd kong-operator
   git checkout v2.4.0
   ```

2. Select the corresponding router flavor and gateway type from the table above. For example, to reproduce the `expressions-standard` report, run:

   ```bash
   TEST_KONG_ROUTER_FLAVOR=expressions \
   KONG_TEST_CONFORMANCE_GATEWAY_TYPE=standard \
   make test.conformance
   ```

3. Check the `*report.yaml` file generated in the repository root.
